# Mandate — Release Checklist

Use this as a hard gate before submitting Mandate.

## Product

- [ ] One-sentence product description matches the actual live build.
- [ ] Primary user and painful moment are obvious on the landing page.
- [ ] Happy path can be completed end-to-end by a fresh wallet/user following documented instructions.
- [ ] No broad feature claims point to unfinished routes or fake data.
- [ ] Sponsor integrations are load-bearing, not logo decoration.
- [ ] Legal/economic language accurately describes PreStocks exposure rather than calling it direct company ownership.

## Onchain program

- [ ] Program builds reproducibly.
- [ ] Program ID/address is recorded.
- [ ] IDL/client artifacts match deployed binary.
- [ ] Upgrade authority/admin authorities are documented and secured.
- [ ] Program verification/current equivalent completed where feasible.
- [ ] Every financial state transition has boundary/adversarial tests.
- [ ] Program pause preserves legitimate exits according to specification.
- [ ] No admin instruction can seize active user funds outside documented rules.
- [ ] No unchecked arithmetic in settlement-critical code.

## Token handling

- [ ] Every enabled mint is exact-address allowlisted.
- [ ] Token program and decimals verified onchain.
- [ ] Token-2022 extensions inspected and documented.
- [ ] Transfer Hook/fee/other active extensions handled correctly.
- [ ] Unsupported extension state fails closed.

## Backend/indexer

- [ ] Chain state can be rebuilt from a clean database.
- [ ] WebSocket disconnect/backfill tested.
- [ ] Duplicate events do not double-count state.
- [ ] External API schema failure tested.
- [ ] Rate limits/timeouts/retries documented.
- [ ] No server endpoint can move a user's funds without the user's required signature/protocol authority.

## Frontend

- [ ] Wallet connect/disconnect/reload tested.
- [ ] Every money-moving action shows exact terms before signature.
- [ ] Pending vs confirmed/finalized state is clear.
- [ ] Error messages map to stable program/API codes.
- [ ] Mobile viewport works for the primary flow.
- [ ] No console errors on the happy path.
- [ ] Contextual prices show source/freshness.

## Security

- [ ] Threat model updated to match final code.
- [ ] Dependency audit reviewed.
- [ ] Secret scanner passes.
- [ ] No `.env`, keypair, API key or seed phrase committed in Git history.
- [ ] Logs scrub authorization headers/private material.
- [ ] Admin/observer/deployer keys are separated appropriately.
- [ ] Mainnet transactions use tiny intentional values during proof.

## Infrastructure

- [ ] Production RPC configured with WebSocket.
- [ ] Database backups configured.
- [ ] Migrations applied through CI/release process.
- [ ] Health/readiness endpoints monitored.
- [ ] Indexer lag alert configured.
- [ ] External provider outage behavior documented.
- [ ] Rollback strategy exists for web/API/indexer releases.
- [ ] Onchain upgrades require explicit release procedure.

## Evidence

- [ ] `docs/FINAL_HANDOFF.md` generated by final Codex audit prompt.
- [ ] Mainnet-fork E2E transcript committed under `docs/evidence/`.
- [ ] Mainnet proof signatures recorded under `docs/evidence/mainnet.md`.
- [ ] No mainnet-fork signature is labeled mainnet.
- [ ] Video/demo uses current deployed product, not an obsolete local build.
- [ ] README setup works from a clean clone.

## Stocklana submission

- [ ] Re-open current official hackathon page.
- [ ] Re-open current sponsor requirements.
- [ ] Confirm selected bounty eligibility.
- [ ] If claiming PreStocks, verify no competing pre-IPO asset integration was introduced.
- [ ] If claiming Clawpump, verify the required Clawpump + stock-paired Meteora launch exists live.
- [ ] If claiming Meteora DBC, verify DBC is genuinely central and working; normal Meteora LP usage is not enough.
- [ ] Project name, live app, repository and technical/demo video URLs all resolve without authentication surprises.
- [ ] Team members are registered correctly.
